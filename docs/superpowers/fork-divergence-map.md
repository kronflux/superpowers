Per-file record of what this fork owns, keyed to [upstream-sync.md](upstream-sync.md)'s

branch; the pre-existing-inventory table only changes when a new fork-owned subsystem lands.

**Generation commands:**

```bash
git diff main...HEAD --name-only                       # full changed-file list
git diff main...HEAD --name-only | grep -c '^\.antigravity-plugin'   # mirror-file count (dedupe target)
git diff main...HEAD --name-only | grep -vc '^\.antigravity-plugin'  # non-mirror file count
git diff main...HEAD --stat                             # insertion/deletion sizes, used to tell
                                                         # "whole-file fork content" from "one pointer line changed"
```

Re-run these against the current `main`/release branch before each resync; `main` is the
upstream-parity baseline this fork branches from, so `main...HEAD` for the branch under review is
the correct three-dot range.

**Snapshot semantics:** Table 1 is a snapshot of the branch that just closed, not a cumulative
history — once a branch merges into `main`, its files drop out of the next release's `main...HEAD`
diff. Regenerating Table 1 therefore means: (1) any row from the outgoing Table 1 that is **not**
touched again by the new branch folds into Table 2 as pre-existing inventory (`main` now carries
it); (2) any Table 2 row the new branch **does** touch moves out of Table 2 and into the new
Table 1. Nature/notes carry over unchanged when a row moves — only its table changes.

## Nature legend

The four base natures from the plan (`router-pointer` / `hook-point` / `net-new` / `overlay`)
plus two extensions this map needed: `moved` (pure renames that filename-matching alone would
misclassify) and `identity` (same-named upstream files with fully diverged fork content):

| Nature | Meaning |
|---|---|
| `net-new` | File or directory has no upstream counterpart at all — fork-authored from scratch. |
| `router-pointer` | File exists upstream too; the fork-owned part is a pointer to a `skills/shared/conductor/*.md` adapter or the routing table. Everything else in the file is upstream-shared prose — apply upstream hunks there directly. |
| `hook-point` | Fork-owned mechanism file: a hook script, a generated manifest, a gate, or a test guarding one. Not skill prose. |
| `overlay` | Generated harness-surface mirror, regenerated wholesale by a sync script. Never hand-diffed; dedupe to one row pointing at the generator. |
| `moved` | Relocated within the fork's own tree. Upstream, if it has an equivalent, still uses the old name/location — do not path-match by filename alone. |
| `identity` (extension) | File exists upstream under the same name/purpose, but fork content is deliberately 100% diverged (branding, contributor policy, byte budgets). Never apply hunks wholesale; port only factual details worth carrying over, as manual prose edits. |
